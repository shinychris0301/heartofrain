Its [manual-release guide](https://www.rustore.ru/help/en/developers/publishing-and-verifying-apps/app-publication/setting-up-publication/instant-app-publishing) says a moderated manual version moves to Ready for publication. Confirm the current Console settings and capture the actual moderation result before advancing the payment build.

## After the first version passes moderation

1. Keep the moderated purchase-disabled version unpublished. Enable RuStore test mode for named testers and verify registered products, their approved rewards and SDK `amountLabel` prices against the Console and the reviewed device grant catalogue. Use the same package and release signing identity. Build a separate explicit sandbox profile for the direct-SDK path; the existing `sdk_client_reported` backend-credit profile is not the requested serverless design. One-time Special products need a separate entitlement decision before they can be sold in this mode.
2. On physical Android, test success, cancellation, interrupted external-bank return, process termination, duplicate callbacks, lost response and repeatable Mega/coin products. Test Special promotions only after their one-time entitlement policy is resolved. Compare the local wallet, inventory, journal intents, receipts and SDK acknowledgements after restart. Neither UI success nor a scripted SDK callback alone is payment acceptance.
3. Test refunds and chargebacks, local reconciliation, backup/restore limits and support procedures. Resolve any non-idempotent or client-trust path before production activation.
4. Build a new non-Development purchase-enabled candidate with versionCode greater than 130 and the same signing certificate. Run native, local-ledger, real-device, Russian localization and upgrade-preservation checks against the exact artifact. Submit it under manual publication; release only after moderation and the direct-SDK acceptance gates pass.
