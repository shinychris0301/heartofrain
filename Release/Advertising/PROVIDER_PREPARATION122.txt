VERIFY CONFIGURATION BEFORE CHANGING THE HOST

Backend/hotr_backend/provider_readiness122.py provides the offline function
assess_ads_and_vk(public_origin=..., vk=..., advertising=..., backend_ads=...).
The combined production-preparation command consumes its sanitized report.
It checks exact VK callback/origin matching, strict enabled booleans, the six
public advertising fields, approved unit IDs, HTTPS privacy URL, client/server
enablement parity and the existing fixed backend reward policy. It reflects no
input values and performs no network, file or account operation.

Disabled configurations can be syntactically valid and still blocked. A report
readyForProviderTest=true means those public values are consistent; it does not
prove published policy, VK app ownership, SDK playback, publisher approval or
production activation. productionEnabled and providerAcceptanceVerified remain
false. Do not use a green configuration report as permission to enable money.

ACCEPTANCE BEFORE RELEASING THESE FEATURES

VK: test actual registration of a new managed guest, explicitly confirmed
sign-in to an existing linked player, browser cancel, manual app return,
duplicate/expired callbacks, interrupted exchange/completion, network loss,
account switch/logout and deletion. Confirm the stable player and wallet are
unchanged after registration, with no extra genesis or automatic wallet merge.
Use two actual accounts and the intended Android build on real HTTPS hosting.

Ads: use the official demo-unit harness for playback testing. The full-game
profile locks the supplied real units; do not insert demo units into that
profile or click live ads while developing. Cover complete/incomplete/cancel,
no fill/load/show failure, duplicate callbacks, background, token renewal,
termination after completion before network reply, interrupted durable-journal
write, reconnect, account change and disable-with-pending-claim recovery. Check
one server credit and authoritative wallet refresh, the three-claim cap, current
server-time cooldown, local midnight, travel and 23/25-hour DST days. Resolve
the retained Review116 Windows journal replacement fault before claiming its
recovery path is qualified. A passing ASGI fixture is not an Android SDK test.

Yandex does not provide server-side rewarded-view verification. This existing
integration is sdk_client_reported_capped. The backend owns the amount, quota,
ownership, atomic credit and durable receipt; an authenticated modified client
can forge up to the capped 1,200 coins/day. Do not invent a provider signature,
shared client secret or public trusted-reward webhook. The configured SDK also
requires AppMetrica; verify the actual privacy/consent behavior on device.

Monitor quota anomalies, interrupted/pending claims and provider failures using
bounded aggregates. Do not use user IDs, tokens, OAuth query strings, ad payloads
or purchase bodies as metric labels. Backend health/readiness alone cannot
prove a completed video or successful VK exchange.
