IMPLEMENTATION

ServerGameplayConfiguration now supports a packaged non-secret staging resource
in addition to the existing explicit Editor/developer and persistent inputs.
One bounded strict parser rejects unknown/duplicate fields, malformed types,
unsafe origins, unsupported mode/version and invalid identity scopes. Packaged
settings require an HTTPS DNS origin and no development-loopback permission.

The active build route remains Launch -> M65_First_Start, whose reviewAlways
flag is false. Existing PlayerProfileHost/ServerGameSession wiring is unchanged;
packaged selection therefore uses that existing managed projection path.

The dedicated package is com.heartoftherain.stagingreview. Outside the Editor,
its packaged configuration is authoritative: external/persistent files cannot
redirect it. A missing payload, wrong package, nondevelopment player, ambiguous
resource or invalid selected input stays managed-unavailable. It never falls
back to an ordinary offline wallet. An ordinary app without any configuration
continues using its existing local profile.

An explicit missing configuration path now fails closed, rather than behaving
as if no server was selected. The existing 83 assertion was deliberately updated
for this case. Legacy UTF8-BOM files remain readable; the packaged asset is
canonical UTF8 without a BOM. No profile, reward, inventory, account or backend
mutation is introduced by parsing/selection.

The Editor staging builder validates a separate project receipt and injects
only canonical public fields at Resources/HOTR_Server/ManagedStaging. It requires
Android Development mode, a separate package and debug signing. Active Android
target is required before real build injection to avoid a target-switch reload.
An early build guard rejects unowned/stale/duplicate/shadow resources, release
or wrong-package builds and an unconfigured staging package. The existing
RuStore release and backend production guards remain in effect.

The preparation tool copies into a fresh owned Unity2022 candidate, changes
only its company/product, Android/Standalone identifiers and custom-keystore
flag before first import, then records exact file hashes. Main Resources,
settings, original GUIDs and offline saves remain separate. No engine/SDK
upgrade is performed.

Temporary resource/meta/folder ownership is checked by exact hashes and a
process-local lease. Cleanup runs on success and failure; foreign bytes are
preserved and block reuse. A persistent marker alone never authorizes a build.
Explicit recovery checks the reviewed marker hash, receipt/nonce, exact owned
bytes and stopped owner process before removing only the owned fixed files.
Build failure reports distinguish attempted work, actual BuildReport counts,
partial output and cleanup/settings restoration; a failed build is not reported
as an unattempted preflight.
