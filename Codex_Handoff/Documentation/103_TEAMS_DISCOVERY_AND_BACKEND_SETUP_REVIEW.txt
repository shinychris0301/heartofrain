103 - Teams discovery and VK/backend configuration

REVIEWED_WITH_OPEN_ACCEPTANCE_GATES: the source repair is verified in the pinned
Unity Editor and the selected backend messaging tests. No APK, device operation,
hosted service, real VK authorization or production activation is part of this
checkpoint. The previously installed APK remains checkpoint 101; its current
physical state has not been inspected in this checkpoint.

CAUSE

The ordinary local TeamsPage selected TeamsDemo.json, which already assigned
the sample player to Rainkeepers. That preview had Chat, Info, Mail and Rankings
but no Create or Join actions. The separate connected Teams implementation
already contained real client requests and backend create/join services.
An ordinary unconfigured local build never selected those services.

REPAIR

Ordinary local Teams now reuses the existing online page's unavailable state.
It displays Create team and Join a team, with an explanation and muted,
non-interactive buttons. It creates no social identity, sample membership,
network command, wallet change or inferred connection. There is no ineffective
retry button in this permanently unconfigured state. Existing sample content
remains an explicit Editor/development review fixture.

Connected nonmembers keep Create team and Join on available directory rows.
Connected members keep Chat, Info, Rankings and Leave in Team Info. The server
enforces one team per player, capacity and durable request idempotency. A leader
with other members must transfer leadership before leaving.

The feature needs a configured managed game account, app socialEnabled=true
and backend HOTR_SOCIAL_ENABLED=1. A managed guest is sufficient; VK linking
is optional. This change does not deploy or enable an online service.
