## Findings, most severe first

### Must fix before these checkpoints are committed

1. **The save-error dialog shown during gameplay now paints Home's blurred chapter art over the paused board and loads the entire Daily Gift design set at that moment.** `App/Profile/Runtime/DailyGiftPage.cs:39-40` (`Build` loads `DailyGiftDesignAssets` and adds a full-screen `RawImage` backdrop) and `:122-123` (`Render` assigns the blurred `home.ProfileBackground` unconditionally, including for `view.error`). `PlayerProfileHost.ShowSaveError` routes every gameplay-time save failure here (`HomeLevelFlow.cs`: booster commit, win commit, faulted release, exit confirm). Before this change the dialog drew a translucent shade over the board; now the board is replaced by Home artwork, a blur render runs, and ~16 textures (≈41 MB uncompressed, finding 3) are loaded mid-level and never unloaded. Fix: for `view.error` skip the backdrop/blur and the design load (shade only), or move the save-error dialog out of `DailyGiftPage`.

2. **A queued "−1" life cue replays after a later, unrelated win.** `App/HomeLivesDesign/HomeLivesPresentation.cs:7` keeps `pending` receipts until `HomeLivesFeedback.Update` can play them (`HomeLivesFeedback.cs:24-26`: Home interactable and `CanOpenAppSettings`); nothing flushes the queue. Lose → retry pre-level (Home non-interactable, the −1 waits) → "Try Again" → win → `FinishCompletion` makes Home interactable → the stale −1 floats over the victory reward reveal, announcing "one life used". Three losses then a win play three −1 cues in a row. Fix: drop pending receipts when a new attempt is reserved/started (or only play receipts newer than the latest attempt).

3. **Uncompressed RGBA32 (+mipmap) policy for 48 registered UI sprites, with ~38 MB loaded at Home start by the loading screen and never released.** `App/UIClarity/Editor/UIClarityRegistry.json` forces `textureFormat: 4` / `textureCompression: 0` / `overridden: 1` on Android, iPhone and Standalone for every entry (≈117 MB if all resident). `HomeLevelFlow.cs:41` calls `GameplayLoadingAssets.Load()` in `Start()` for every session: `Rain_Seeker_Original` and `Rainbow_Orb_Original` are 1254² with mips (≈8.4 MB each, drawn in a 146-unit slot), `LT_Background` 1080×1920 (≈8.3 MB), `LT_Orb_Links` 1440×960 (≈5.5 MB), four 512² tiles with mips (≈5.6 MB), two buttons (≈1.2 MB). `App/UIClarity/Editor/UIClarityGuard.cs:109-117, 252-261` fails any player build whose registered sprite is compressed, atlased or not overridden, so the ASTC/ETC2/atlas work doc 57 lists as "open" cannot ship without editing the guard. Doc 63 lists GPU/memory as open; the cost itself is not measured on any device. Fix: load the loading-screen art lazily on first Play (as the other pages do) and release it on handoff; decide the compression policy per sprite (ASTC for photographic art, RGBA32 only for small vector-edged slices) and make the guard express that policy instead of forbidding compression.

4. **The offline Account screen promises a cloud save that does not exist.** `App/AccountDesign/AccountModal.cs:80` shows `offlineIntro` ("Connect to the internet to save your journey to the cloud") whenever `LocalAccountService` reports offline (`AccountService.cs:29`), with a Retry button; the "linking unavailable" disclaimer is emitted only in the online `save` branch (`:67-71`). With no backend this is the case AGENTS.md forbids (claiming backend work because a page renders). The online guest view is honest (providers disabled, explanation shown). Fix: offline copy must say the save is local, not that reconnecting enables cloud save.

### Should fix

5. **The lives expiry refresh bypasses the host's gates and rebuilds Home.** `HomeLivesFeedback.cs:23` calls `host.Refresh()` whenever the countdown reaches zero, gated only on `home.PresentationVisible`; `Refresh → Apply → home.ApplyState` (`PlayerProfileHost.cs:96`) runs a full `Reflow` and stops `RevealReward` (`HomePage.cs:136-137`). `PlayerProfileHost.Update` deliberately gates its own refresh on `!RewardRevealPlaying && CanOpenAppSettings`; the new path fires during the reward reveal (coins snap to their final value, Home rebuilt) and behind the pre-level/loading overlays, duplicating `HomeLevelFlow.Update`'s `LifeDue` refresh. Fix: route the expiry through the host's existing `LifeDue` refresh (same gates).

6. **A disabled Claim button draws a 65 % black rectangle behind its rounded art.** `DailyGiftPage.cs:121` dims every `Graphic` under the `claim` node, including the node's own clear hit `Image` (`Color.clear → (0,0,0,.65)`), whenever the button is non-interactable (loading; and the default release state with `UnavailableGiftAuthority`). Visible in `Verification/Evidence/DailyGiftR1/Loading_Fixture.png`. Fix: skip the node's own graphic, as the feedback setup two lines above already does.

7. **Three existing Editor suites' layout/text checks became vacuous while the docs still cite their counts.** `Verification/Editor/BackendGiftUIVerification.cs:31`, `WellworksVerification.cs:50` and `RainCupVerification.cs:60` iterate `elements.Where(e=>e.parent=="panel")`; in the redesigned frames the panel's direct children are only `shell`, `header`, `viewport`, `footer`, so zero text-bounds/glyph assertions run and the "approved asset" check covers one chrome sprite (the 736 "layout" checks of doc 56 are 5 locales × 3 widths × 7 states × 7 trivially true checks + 1). `ProfileTransactionVerification.cs:124-128` measures text with `DailyGiftPage.FitText` and the bold font, but the live page now renders body text with `design.bodyFont` and its own wrap loop (`DailyGiftPage.cs:112-114`), so that measurement no longer describes the rendered page. Real coverage exists only in the new `*R1Review.LayoutChecks` on live `Text` components. Fix: point the old suites at the new frame (`viewport`/`footer` subtrees) or retire them, and correct docs 56/58/59.

8. **Approved artwork bytes were replaced and the Account R6 frozen evidence no longer matches.** `App/Profile/Art/CheckSource.png` 58×59 (6,436 B) → 232×236 (18,599 B) "vector reconstruction" (GUID, pivot and border preserved; consumers use fixed rects, so no layout break). `Verification/Evidence/AccountR6/Source_SHA256.json` still records the old `CheckSource.png`, `CheckSource.png.meta` and `Primary.png.meta` hashes, so doc 55's "artwork hashes unchanged" is stale and its collector would now reject the inputs. AGENTS.md: approved artwork is preserved unless the task explicitly changes it — this needs the owner's sign-off, then a re-collected AccountR6 evidence set.

9. **Rain Cup name ellipsis still splits surrogate pairs.** `App/Profile/Runtime/RainCupPage.cs:98` trims one UTF-16 unit per step; `ProfileRules.TryName` accepts emoji names, so a long emoji name is cut inside a pair (missing-glyph box before "…"). `ProfilePage.cs:185-186` already does this correctly with `StringInfo.ParseCombiningCharacters`; reuse it. (Carried over from the checkpoint-60 backlog; the redesign did not touch it.)

10. **Escape on the loading failure screen can also close the pre-level.** `GameplayLoadingPage.cs:59` invokes `BackRequested` on a frame-wide `Escape`; `BackFromLoading` hides the overlay and re-shows the modal in the same frame, and `PreLevelModal.cs:49` tests the same key (gated only by `data.busy`, now false). Today the modal's `Update` happens to run first, so the press is ignored there; the order is not guaranteed. Fix: have the loader set the existing `ConsumedInputThisFrame`-style guard the celebrations use, or let `BackFromLoading` defer the modal by a frame.
