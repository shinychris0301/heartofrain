# 124 — Social navigation and local diagnostics

31 October 2026. The tested Android package is the separate staging app com.heartoftherain.stagingreview, built with Unity 2022.3.62f3. The ordinary installed game and production backend were not changed.

## Findings and changes

The earlier cold Teams entry took 2,803 ms on the realme phone. Serial server reads, first-use artwork loading, synchronous UGUI construction and protected owner checks contributed. Teams now warms read-only data, artwork and its canvas while Home is visible. It reuses the frame on return and keeps known content visible during a background refresh. Social writes still require the durable, protected owner and outbox checks. The navigation journal stores only event codes, UTC seconds and bounded durations; it contains no message text, account IDs, URLs or credentials.

Teams, Friends and Leaderboard no longer show transient Loading labels. Offline Teams and Friends show one localized notice with Retry, and Leaderboard uses its own offline wording. Read-only tabs remain locally navigable during GET requests. The phone captured Teams chat, Mail, Players World and Friends without a full-page loading state. No chat message, life request, purchase or other server mutation was submitted in this pass.

An offline LDPlayer launch exposed a misleading Home balance: the unavailable server projection appeared as zero coins and 0/5 lives. The live scene and Home defaults no longer contain the old sample wallet. When the server wallet is not ready, Home and the life feedback component now show neutral dashes instead of presenting unavailable values as spent currency or lives. On the phone, the same updated APK displayed its existing 1,250-coin, 5/5-life server wallet. The Editor review Reset action still uses explicit sample values.

The phone Shop briefly displayed a pending video-reward check while no ad provider was installed. The Shop view now presents the unavailable state immediately in that case. An actual unresolved reward still exposes its retry action; no reward or purchase authority was moved into presentation code.

The Teams chat view previously made a deep JSON copy of life-request data while holding a read-only presentation lease. It now reads the presentation snapshot directly. Command paths still use their defensive copies and the server remains authoritative. This removes one avoidable main-thread allocation and copy on chat presentation.

The first Teams frame also copied team details to calculate chat-composer availability and leave-dialog state. It now derives the composer flag from the already leased team view and calculates leave-dialog state only when that dialog is open. The editor checks passed, but the measured first-entry latency on the phone overlapped the previous build; this narrower copy reduction is not credited as a proven speed improvement.

The bounded navigation recorder now validates its contiguous event-code range without reflection on each sample. A diagnostic build split the first chat-view phase into Mail, Life and Availability. Their measured work was 8, 0 and 1 ms, while the enclosing phase took 173 ms. The gap occurs around the first call boundary or its timing marker; the current evidence does not distinguish method compilation, garbage collection and recorder overhead. The change to event validation did not produce a measured first-entry speed gain.

## Remaining limits

The measured 407-480 ms first Teams entry is perceptible, so instant first navigation is not achieved. The realme phone can show server team data, but LDPlayer and this PC still time out waiting for the staging HTTPS TLS response; their captures establish offline behavior only. The Shop video button remains unavailable because this staging build has no usable ad provider, and its price cards are review pricing rather than a proven live checkout. This pass did not verify live two-phone chat delivery, reward claims, purchases, long-session frame pacing or Match Villains latency parity. The Android build report's two warnings have not been attributed to a cause. Further first-entry work should profile method first use and Teams UGUI rendering on the physical phone, including a release-like IL2CPP build before attributing the gap to Mono JIT.

The local diagnostic file is limited to 256 samples and 32 KiB on load, saved on pause or quit. It is a performance aid, not durable gameplay state or a crash-complete trace.
