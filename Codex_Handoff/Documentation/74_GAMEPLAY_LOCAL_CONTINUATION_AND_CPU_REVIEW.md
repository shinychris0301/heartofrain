# Local cascade continuation, command cost and frame attribution

24 October 2026. **PASS_TARGETED_GAMEPLAY74_WITH_REMAINING_PERFORMANCE_GATES.** Unity remains 2022.3.62f3. Checkpoint 74 is rebuilt, installed and verified on QA LDPlayer; main LDPlayer retains deployment 64. All native and Android stages pass. This is a targeted responsiveness repair with measured command and dense-render stalls still open.

## Changes under verification

The reproduced level 4 match no longer needs to wait for every moving body in its affected column. `M46/Runtime/LocalCascadeContinuation.cs` permits one restricted vertical continuation. A shared body retains its original flight, spawn clipping, stretch and landing, then begins its next column-retimed flight. Other unfinished bodies retain their original paths and clocks. A uniform per-column adjustment preserves successor headway and waits for prior landings. Snapshot identity, raw model events, random outcomes, goals and transactions remain model-owned.

`BoardPlayback.cs` selects the new pass by default and retains explicit sequential and checkpoint 73 controls. `TileFall.Position`/`Moving` and `BoardPresentation.cs` select the original motion segment for each pose. `FeedbackPlanPure.cs` transfers pending old landing contacts and keeps the new ones, without replaying a contact already handled at the handoff.

The pass rejects unsupported powers, deliveries, advanced obstacles, intersecting side feeds, obstacle mutations in moving columns, unordered old routes, unsafe padding and unfinished ownership at the successor boundary. It permits at most one continuation per turn. Other cases use the checkpoint 73 scheduler. Only one of the 350 established sample commands qualifies; this repair does not make every cascade locally immediate.

`BoardModel.cs` adds an existence query for Settle/Shuffle. Those callers only need to know whether any legal swap exists; they previously enumerated the complete public list. The new query stops at the first legal action and restores the trial exchange before returning. Public `LegalSwaps` keeps its existing ordered results for hints/replays. The protected newborn rule and 900-coin life refill remain regression requirements.

Gravity now creates its full before-snapshot only when a vertical segment or side feed will actually change the board. Unchanged segments retain their original remove/reinsert order. The native reference controls compare all emitted steps, random state, next identity, dirty IDs and dictionary enumeration; the archived 350-command comparison remains authoritative for authored behavior.

`M46AtlasBank.cs` snapshots references to already-created effect sprites. `EffectMeshBatcher.cs` prepares at most 2,048 quad descriptions and reserves 32 disabled mesh slots during the existing level initialization. A two-millisecond work budget yields only when actual preparation work reaches the budget; there is no minimum dwell. Later frames and larger bursts keep the existing demand path. Texture loading, sprite pinning, the 4,096-entry geometry flush, authored rendering, mesh upload and material behavior are preserved. The reserve does not pre-upload GPU vertex buffers or eliminate all future allocation.

The cache review also found an initialization race: the largest authored set has 2,522 common/obstacle frames, but the sprite allowance previously expanded only after obstacle preparation completed. Live Render can evict unpinned common frames at an intermediate yield even while texture eviction is blocked. The allowance now expands with the pinned set before each yield, preserving the existing final budget. A real-bank interleaving control and an actual Play Mode load verify retained common sprite identities at readiness. This newly isolated race is not labelled as the cause of the historical 183 ms interval.

The source audit also found that `EffectBatchingEnabled` was nested inside a development-only region although normal rendering calls it. Its property now exists in both build configurations. The actual final-source non-development Android build passes with zero errors; development compilation alone would not prove that branch.

## Corrected measurement

Checkpoint 73's separate level 4 run recorded one 183 ms interval. Its aggregate report lacks a frame/phase identifier, so that interval's exact cause cannot be recovered. The old probe solved the model and built an extra diagnostic playback before starting its wall timer; real Accept then built it again. That unmeasured work could appear in the following interval. The old result remains historical evidence, without relabelling it as proven rendering or scheduler cost.

`CascadeTimingProbe.cs` now inspects the actual accepted queue instead of building it again. It separates fixture/legal-search work, model execution, actual Accept and queue inspection. Bounded pre-roll/playback/post frames include absolute timestamps, current state, separately tagged Update/Render state, GC/resource counters and command-frame tails. Optional repeats reload boards and banks; only process/code/driver paths are warm.

Development-only `GameplayScreen.cs` counters split Enqueue construction, initial phase selection, dependency discovery and prefetch dispatch. Render counters split sampling, bank lookup, batch construction, mesh upload, SpriteRenderer updates and bank eviction. `EffectMeshBatcher.cs` counts first-use geometry and new slots; mesh rendering behavior is unchanged. `ObstacleDensityProbe.cs` records these same tagged costs for its dense fixtures. These diagnostics add overhead and do not measure touch-to-photon latency or GPU completion.
