State-to-action mapping
locked: show service completion progress toward 10; disabled Locked action.
ready: show Join; join only when the authoritative state allows enrollment.
active: show score and rank; Play opens the existing pre-level flow.
results: show authoritative final rank and corresponding unclaimed prize.
claimed: show collected marker; Done closes the overlay.

Keep the Practice event / Simulated rivals label visible in this practice mode.
No invented timer, cycle reset, enrollment deadline or event-duration rule is
included. More than five participants may be returned by the real service;
render the full list and user's actual rank without clamping to five.
The supplied reference defines five prize tiers, not five total participants.

Production service bindings
- Read authoritative eventId, state, completed qualifying levels, enrollment,
  score, standings, finalRank and claim status; preserve the existing service.
- One point is earned only from a confirmed qualifying NEW-level completion.
  Play taps and replay completions must not award points.
- Map semantic reward IDs coins/rocket/bomb/hammer to existing inventory IDs;
  Rocket and Bomb remain independent quantities and assets everywhere.
- Join/Claim requests disable duplicate submission while pending. Use the
  service's idempotency mechanism scoped to player/event/claim. Apply inventory
  changes from its acknowledged authoritative grant, once.
- On failure retain the unclaimed state, show the localized retry message and
  refresh the authoritative event before retrying if outcome is unknown.
- Closing or changing the UI stops presentation only. A request accepted by the
  real service may still succeed; reconcile on reopen rather than canceling a
  transaction based on the preview's animation token.
- Never mark a whole event complete because a sample score reaches 16. The
  preview's result scenario is a fixture, not a gameplay trigger.

The review intentionally uses no persistence and no real network or inventory.
Its raincup:playRequested browser event represents a handoff only. Do not copy
demo state transitions, sample rivals or the 380ms artificial wait into the app.
